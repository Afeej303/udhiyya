## V2 – Manual UI Check (≤ 5 minutes, run by M1 or M2)

**Checklist file:** `docs/VERIFICATION/EF-02.md` (this file)

### Setup
1. Set `FEATURE_EF_02=on` in `.env`.
2. Ensure the backend is running and seeded with ≥ 1 programme, ≥ 7 approved participants, ≥ 1 unallocated animal.
3. Navigate to the **Allocations page** (the slot `smart-allocation-slot` must be mounted by M1).

### Steps

| Step | Action | Expected result |
|---|---|---|
| 1 | Open Allocations page with flag on | `SmartAllocationPanel` renders with policy selector and **Run Smart Allocation** button (`data-testid="ef02-smart-allocation-btn"`) |
| 2 | Click **Run Smart Allocation** | Loading state shown (`data-testid="ef02-loading"`); button disappears |
| 3 | Wait for response | Preview table appears (`data-testid="ef02-preview-table"`) with participant names, animal tags, share numbers (1–7) |
| 4 | Verify no animal exceeds 7 rows | Count rows per animal tag in the table; each should be ≤ 7 |
| 5 | Click **Confirm & Commit** | Success message shown (`data-testid="ef02-success"`) with committed count |
| 6 | Refresh Allocations page | Previously matched participants no longer appear as unallocated |
| 7 | Set `FEATURE_EF_02=off`, reload page | Panel disappears cleanly; rest of page unaffected |

### Pass criteria
- All 7 steps produce expected results ✅
- No JS console errors
- MVP allocation page still works with flag off
